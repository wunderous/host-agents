# Update the TUI v2 redesign plan for today's architecture and mark RFC 0001 as an unscoped exploration

Documentation-only change — two markdown files, no code.

## Summary

The TUI v2 redesign plan (`opute/.agents/plans/2026-08-host-agent-tui-redesign.md`) predates the `clients/tui` module split and still points at the stranded `internal/tui` location, so it can't guide implementation today. This update rebases it onto the current architecture (separate `clients/tui` module, ADR 0002 boundaries, existing typed-draft core), adds an implementation-phase section with real file paths, and records what is already built vs. missing. Separately, RFC 0001 in the host-agent repo gets reclassified from "Tentative proposal" to an unscoped exploration so it stops reading as a competing, newer direction.

## What I verified

- **ADR 0002** (`opute-host-agent/docs/adr/0002-provider-extension-architecture.md`) is the deciding context: it calls the redesign plan "authoritative for the TUI's typed draft, deterministic execution, agentic review, inspector, operation projection, and no-LLM behavior," mandates "New TUI behavior belongs in `clients/tui`," and defines binding TUI invariants (I-29–I-38, I-48, I-51). The ADR references the redesign plan **by path**, so the file must be updated in place, not renamed.
- **Already implemented in `clients/tui`**: `CommandDraft`/`EntityBinding`/`OutputBinding` types and the fail-closed `ValidateDraft`/`ExecuteDraft` executor (`clients/tui/internal/tui/client.go`), `@vm:` entity resolution (`app.go:101-128`), durable operation polling that reconnects without replaying mutations (`operation.go:21`), the deterministic REPL (`app.go:28`), the packaged no-LLM vertical-slice test (`test/tui/packaged_test.go`), and the enforced boundary test forbidding `clients/tui` from importing `internal/` (`test/contract/architecture_test.go:25-29`).
- **Not implemented**: the full-screen two-pane rendering, inspector panels, live catalog-driven completions/editor states, approval/gated display, and agentic mode. The Bubbletea model to port lives at `internal/tui/interactive.go` (unreachable legacy, porting reference only).
- **Stale in the current plan doc**: its References section points at `../../opute-host-agent/internal/tui` and `internal/tools/capability.go`; it has no awareness of ADR 0002 or the module split.
- **Coordination hazard found**: the untracked `2026-08-23-resource-uri-scheme-plan.md` will move the TUI off `vmName=@vm:worker-01` tokens to URI tokens (`clients/tui/internal/tui/client.go` `EntityBinding` gains `URI`). The updated plan must reference it so the two efforts don't collide in the same files.
- RFC 0001 status is currently "Tentative proposal" dated 2026-08-22; its phase 7 ("Remove Bubble Tea, embedded TUI…") is what makes it read as superseding the TUI work.

## Decisions

- **Update the redesign plan in place rather than fork a new dated doc** — ADR 0002 references it by path; renaming would break a normative citation. The doc gets a "Revised 2026-08-23" header instead.
- **Full-screen target is Bubble Tea inside the `clients/tui` module** (new deps in `clients/tui/go.mod`: `charmbracelet/bubbletea`, `bubbles`, `lipgloss`, `x/term`) — mandated by ADR 0002 I-48/I-51; not an open choice.
- **Terminal gating mirrors the legacy `useBubbleTea` rule**: alt-screen UI only when stdin and stdout are TTYs and `--no-prompt` is unset; the line REPL remains for pipes/automation so `test/tui/packaged_test.go` keeps passing unchanged.
- **Agentic mode explicitly deferred** in the updated plan (optional per ADR 0002, LLM-independence invariants I-29/I-32/I-33); first phases are deterministic-mode-only.
- **Legacy `internal/tui` removal becomes a final, gated phase** (after feature parity, root `go.mod` drops its bubbletea deps) — consistent with ADR 0002's "retained only as an unreferenced compatibility fixture during cleanup."
