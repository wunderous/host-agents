Use cases

Inspect before you act

Host Agent exposes typed operations through authenticated MCP. Begin by reading the host and discovering its current catalog. The available catalog is a host capability description, not proof that an optional provider is configured.

Understand the connected host

Call get_host_info {} to read the host URI, hostname, provider identity, and supported tools. Use this result to confirm which Host Agent answered before asking for a resource inventory.

Discover operations available now

Call get_capability_catalog {} and inspect its revision and declared effect. Refresh tools/list after connecting; live discovery is authoritative for that process.

Inspect VM inventory when Incus is configured

Call list_vms only on a host with its Incus provider available. This is inventory discovery; creating, changing, or deleting a guest is a separate mutating operation and is outside the first-success tutorial.

Discover Kubernetes clusters when configured

Use list_kubernetes_clusters only when the host has an available Kubernetes provider and the intended source is known. An empty inventory and a failed inventory probe are different outcomes; read the structured response and error status.

Product boundary. Host Agent executes explicit typed operations against one host. Platform owns intent, authorization, and durable orchestration across hosts. Read how they fit together.

These examples describe verified tool names and their documented purposes. No customer outcome, performance result, or availability guarantee is implied.
