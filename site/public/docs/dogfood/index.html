How-to

Publish this site

Public source builds the static-site image. A private deployment controller selects the successful image and submits the private Host Agent recipe on the serving machine.

Ownership

  • Public source: wunderous/host-agents owns site content and publishes GHCR images from GitHub-hosted CI.
  • Private deployment: wunderous/opute-site-deploy owns source-run selection, the Kubernetes manifest, the deployment workflow, and the Host Agent recipe. Repository access is required.
  • The private controller deploys the image by immutable sha256 digest. Its runner is registered only to the private repository and calls the local Host Agent.

Public source CI has no Host Agent credentials and never runs on the deployment machine.

Flow

flowchart LR
  SRC[Public site source] --> BUILD[GitHub-hosted image build]
  BUILD -->|run tag and digest| REG[(Public GHCR image)]
  POLL[Private controller] -->|verify successful main run| REG
  POLL --> RECIPE[Private host-recipe.v1]
  RECIPE -->|typed Host Agent tools| HA[Local Host Agent]
  HA --> K3S[Admitted K3s cluster]
  K3S --> SITE[Site workload]
  SITE --> TUN[Dedicated public tunnel]
  CLIENT[Public browser] --> TUN

Path of record

  • Source image workflow: .github/workflows/publish-site-image.yml in the public source repository
  • Deployment workflow, manifest, and recipe: private repository wunderous/opute-site-deploy
  • The controller checks the source run, resolves its run-and-attempt tag to a digest, then calls run_host_local_recipe

The recipe is the only cluster mutation path. Ad-hoc kubectl is not accepted as deployment evidence. Scheduled runs do not fall back to an older image; rollback requires an explicit successful main run.

Isolation invariants

What pass means

  • The Host Agent recipe reaches terminal success and the Deployment uses the selected digest with a Ready Pod.
  • External /build.json on both www and apex matches the selected source SHA, run ID, and attempt.
  • platform.opute.io and mcp.opute.io remain separate and healthy.
Site reachability is not two-node write / etcd-quorum HA. Report application readiness separately from cluster consensus availability.

Credentials

Host Agent credentials remain in the local Host Agent process environment. They are not copied to GitHub secrets, the public repository, image layers, logs, or workflow artifacts. Tunnel provider credentials remain on the Host Agent/provider side; the public source workflow only publishes the static image.
