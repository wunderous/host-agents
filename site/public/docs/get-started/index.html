Tutorial

Get started

Outcome. Start Host Agent locally, connect VS Code over authenticated HTTP, refresh the live tool list, and read host facts with get_host_info {}. This tutorial does not enable mutations.

Verified release. This path pins the published package whose authenticated read-only canary passed for the catalog revision shown in the capability reference.

Prerequisites

  • Linux or WSL2, Node.js 18 or newer, npm, and VS Code with HTTP MCP support.
  • curl and openssl; loopback port 3014 must be free.
  • Network access to npm and the matching Linux binary in GitHub Releases.

Start the local agent

  1. Set an explicit identity and random secret

    Keep the token in your shell and VS Code prompt. Do not commit it or put it in screenshots.

    export OPUTE_REMOTE_AGENT_ID="local-$(openssl rand -hex 8)"
export MCP_AUTH_TOKEN="$(openssl rand -hex 32)"
npx -y @opute/host-agent@0.2.0 start --background

    This starts the pinned published package shown on this page. Stop the background process with npx -y @opute/host-agent@0.2.0 stop.

    curl -i -sS http://127.0.0.1:3014/health

    Expect HTTP 200 and the exact agentId you set. This open endpoint proves liveness only, not MCP authentication.

  2. Connect VS Code

    Create .vscode/mcp.json. VS Code documents this HTTP server and password-prompt setup in its MCP configuration reference.

    {
  "inputs": [{"type":"promptString","id":"opute-host-token","description":"Local Opute Host Agent token","password":true}],
  "servers": {"opute-host-agent":{"type":"http","url":"http://127.0.0.1:3014/mcp","headers":{"Authorization":"Bearer ${input:opute-host-token}"}}}
}

    Start the server and enter the same shell token. Avoid committing the config if the client might persist the entered value.

  3. Refresh tools and read the host

    Confirm the server is connected, refresh its tools, and call get_host_info with {}. Its schema requires these host facts:

    {
  "uri": "host:example:host-01",
  "hostName": "…",
  "providerId": "…",
  "lxcBinaryPath": "…",
  "systemctlPath": "…",
  "supportedTools": ["…"]
}

    Those six fields are required by the current schema. Optional fields such as agent, capacity, and system appear only when observable. Values are redacted; this is an example shape, not captured host output. A listed capability does not prove its provider is ready.

Keep this first check read-only. Do not set OPUTE_STANDALONE_ALLOW_MUTATIONS=true or call a tool whose declared effect is not read.

Verify the authenticated path

Check that authentication rejects a deliberately wrong token before completing the valid call in VS Code:

curl -i -sS http://127.0.0.1:3014/mcp -H 'Accept: application/json, text/event-stream' -H 'Content-Type: application/json' -H 'Authorization: Bearer intentionally-wrong' --data '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

Expect HTTP 401. A request with no Authorization header also returns 401. Use the real token only in your local shell and VS Code password prompt.

  • No token or a wrong token gets HTTP 401.
  • The configured token connects VS Code; non-empty tools/list includes get_host_info.
  • get_host_info {} returns structured facts and the selected identity.
  • No mutation flag was enabled and no mutating tool was called.

Troubleshoot

  • Port in use: Check the launcher with npx -y @opute/host-agent@0.2.0 status, stop it if needed, then choose an unused HOST_MCP_PORT and use that same port in curl and VS Code.
  • 401: match the VS Code input to MCP_AUTH_TOKEN; restart after changing shell environment.
  • Empty tools: refresh the server, verify the URL ends in /mcp, and check tools/list.
  • WSL reachability: run VS Code and the agent in the same WSL context first.
  • For other symptoms, see troubleshooting.
