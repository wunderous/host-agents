How-to

Connect an MCP client

Connect VS Code to a Host Agent running in the same Linux or WSL context. The documented path uses Streamable HTTP and a password-prompted Bearer token.

VS Code

  1. Start Host Agent on loopback and retain MCP_AUTH_TOKEN in the same shell.
  2. Create a workspace .vscode/mcp.json with an HTTP MCP server and a password input:
{
  "inputs": [{"type":"promptString","id":"opute-host-token","description":"Local Opute Host Agent token","password":true}],
  "servers": {"opute-host-agent":{"type":"http","url":"http://127.0.0.1:3014/mcp","headers":{"Authorization":"Bearer ${input:opute-host-token}"}}}
}
  1. Start the server from VS Code and enter the local token at its prompt.
  2. Refresh tools and call get_host_info {} to confirm the authenticated path.

See the official VS Code MCP configuration reference. This site has not yet recorded a human client run for a specific VS Code release; see compatibility evidence.

WSL and local networking

Keep the editor MCP client and Host Agent in a networking context where 127.0.0.1:3014 reaches the agent. Start with both in the same WSL distribution. If VS Code runs on Windows while the agent runs in WSL, follow the editor's current WSL integration guidance and verify connectivity before configuring MCP.

Other clients

Other clients must support Streamable HTTP MCP and the required Bearer header for this setup. Client-specific recipes are not published as tested until a named version completes the read-only canary.
