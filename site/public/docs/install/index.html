How-to

Install & run

Choose a local source build or the published npm launcher. For a tested end-to-end setup, begin with the first-success tutorial.

From source

From the Host Agent repository root, build and start the standalone HTTP server. Host inspection does not require Incus or Kubernetes.

make build VERSION=0.2.0
export OPUTE_REMOTE_AGENT_ID="local-$(openssl rand -hex 8)"
export MCP_AUTH_TOKEN="$(openssl rand -hex 32)"
./dist/opute-host-agent serve --mode standalone --transport http

Keep both values in your local shell. The agent ID is an explicit opaque identity; the launcher does not invent a default. The token authenticates MCP requests.

Published npm launcher

export OPUTE_REMOTE_AGENT_ID="local-$(openssl rand -hex 8)"
export MCP_AUTH_TOKEN="$(openssl rand -hex 32)"
npx -y @opute/host-agent@0.2.0 start --background
npx -y @opute/host-agent@0.2.0 url
npx -y @opute/host-agent@0.2.0 status
npx -y @opute/host-agent@0.2.0 stop

The launcher keeps the explicit identity and token in the child process. Stop the background process when you finish.

Set HOST_MCP_BIND_HOST and HOST_MCP_PORT when needed. Keep a local tutorial on loopback and use the same port in the agent URL and client configuration.

Mutations

Standalone mutations are denied by default. This first-success path stays read-only. Only enable OPUTE_STANDALONE_ALLOW_MUTATIONS=true after reviewing the capability effects, approval requirements, and host-local consequences.

WSL and production

For a first client connection, run the Linux agent and VS Code integration in the same WSL environment. Verify reachability before configuring a client across Windows and WSL.

Production hosts are connected through Opute Platform's Connect Remote Host flow. Platform owns enrollment and authorization; use the generated host configuration for that host rather than copying local tutorial credentials.
